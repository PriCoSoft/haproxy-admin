How it works
  1. certbot calls the built-in hook for each name. The hook picks the provider by domain.
  2. If _acme-challenge.<domain> is a CNAME (delegation), the TXT value is written at the CNAME target.
  3. The hook waits until all authoritative name servers serve the value, then – after the last name – one TTL, so no resolver still holds an older copy. This avoids the "Incorrect TXT record" failures of back-to-back requests.
  4. After validation the value is removed again (for providers whose API can delete records – see "auto cleanup").

Credentials are stored in /etc/haproxy-admin/dns-providers.json (root only) and never sent back to the browser.
